# Phase 3-0 — D4 Live Acceptance Gate

## الهدف

إغلاق بوابة القبول الحي لـ Phase 2-D4 قبل أي توسع معماري في Phase 3. هذه المرحلة **لا تغير منطق الإنتاج** ولا تضيف ميزة للمستخدم؛ وظيفتها منع البناء فوق مسار لم يثبت حيًا بعد.

## ما تم إثباته محليًا على v0.0.66

- `npm run check`: 492 passed, 0 failed.
- TypeScript build: PASS.
- المسار الإنتاجي يستخدم `AssessmentGenerationJobService` و`AssessmentGenerationWorkerService` و`ProgressiveAssessmentGenerationOrchestrator`.
- التوازي مضبوط على مهمتين.
- `ready` ليست حالة قابلة لإعادة الإرسال.
- استعادة الدورة بعد تحديث الصفحة مغطاة باختبارات D4.
- المسار الإنتاجي لا يستدعي `generateWholeExam` ولا ينشئ `QuestionGenerationService` القديم.
- وظيفتا Edge المطلوبتان موجودتان داخل المشروع:
  - `assessment-generation-jobs`
  - `assessment-generation-worker`

يمكن إعادة فحص جاهزية الكود بالأمر:

```bash
node scripts/check-phase-3-0-readiness.mjs
```

## ما لا يمكن إثباته داخل بيئة تجهيز محلية

لا توجد هنا جلسة مستخدم حقيقية لمشروع Supabase ولا مفتاح Gemini الخاص بالتشغيل. لذلك لا يجوز إعلان D4 `live-stable` اعتمادًا على Unit/Integration mocks وحدها.

## اختبار القبول الحي الإلزامي

استخدم مسودة جديدة أو غير مكتملة مرتبطة بمصادر مفهرسة، ثم نفذ دورة توليد فعلية واحدة. يجب تسجيل PASS/FAIL لكل بند:

1. **الانتقال الفوري**: بعد الضغط على «التالي» تظهر صفحة التقدم قبل اكتمال أي سؤال.
2. **عاملان كحد أقصى**: لا تظهر أكثر من مفردتين في مراحل `grounding/generating/normalizing/validating` في اللحظة نفسها.
3. **أول نتيجة مبكرة**: تظهر أول مفردة جاهزة بينما لا تزال مفردات أخرى قيد العمل.
4. **حفظ المكتمل**: المفردة الجاهزة تبقى ظاهرة ومحفوظة فور وصولها.
5. **اختبار Refresh**: حدّث الصفحة أثناء وجود مفردات قيد التوليد.
6. **استعادة الدورة**: بعد التحديث تعود الدورة نفسها ولا يبدأ Run جديد بلا سبب.
7. **عدم إعادة الجاهز**: المفردات التي كانت `ready` قبل التحديث لا تعود إلى `queued/generating` ولا يزيد `attemptCount` لها.
8. **إعادة الفاشل وحده**: إذا وجدت مفردة `failed` أو `retry_pending`، أعدها وحدها وتأكد أن بقية المفردات لا يعاد توليدها.
9. **اكتمال الاختبار**: يصل العدد النهائي والدرجات إلى الخطة الرسمية دون فقد مفردة مكتملة.
10. **المرئيات بعد المحتوى**: تبدأ مهام الصور المحسنة بعد اكتمال المحتوى، ولا تمنع ظهور الأسئلة الجاهزة.
11. **Word**: التصدير إلى Word ينجح بعد اكتمال الدورة.
12. **PDF**: طباعة/تصدير PDF ينجح بعد اكتمال الدورة.
13. **الاعتماد**: اعتماد الاختبار يبقى فعالًا ولا يعيد المستخدم إلى مسار التوليد القديم.

## دليل القبول المطلوب

يكفي للاعتماد الاحتفاظ بأدلة بسيطة قابلة للمراجعة:

- لقطة شاشة أثناء وجود مفردتين نشطتين وواحدة جاهزة على الأقل.
- لقطة بعد Refresh تبين بقاء المفردات الجاهزة.
- لقطة/تسجيل للمفردة المعادة وحدها إن حدث فشل قابل للمحاولة.
- Word أو PDF نهائي من الدورة نفسها.

## قرار البوابة

- إذا نجحت البنود 1–13: **D4 LIVE ACCEPTANCE = PASS**، ويمكن بدء Phase 3-1.
- إذا فشل أي بند إنتاجي: **D4 LIVE ACCEPTANCE = FAIL**، ويُعالج الخلل كـ D4 Fix مستقل قبل Phase 3.

## ما لن نفعله قبل PASS

- لا حذف للمحرك القديم.
- لا Objective Capability Profiles.
- لا Science Validator Framework جديد.
- لا Pattern Fingerprint جديد.
- لا تعديل لعقود المرئيات أو المصادر.

السبب بسيط: التوسع فوق مسار إنتاجي غير مثبت حيًا يحول الخطأ الواحد إلى عائلة أخطاء كاملة، والعائلات البرمجية للأسف لا تدفع إيجارًا.
