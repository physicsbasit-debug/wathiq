# Phase 1-C1 Fix 1 — Stable Mark-Scheme Contract

## المشكلة

كانت وظيفة `generate-source-questions` تطلب من Gemini إعادة `markScheme` كمصفوفة يجب أن يساوي طولها عدد درجات المفردة. مخطط JSON المشترك لم يكن قادرًا على فرض طول مختلف للمصفوفة لكل مفردة داخل الدفعة، لذلك كانت بعض الاستجابات الصحيحة بنيويًا تعيد نقطة واحدة فقط لسؤال من درجتين أو ثلاث، فيرفض الخادم المفردة كلها.

## الحل

أصبح عقد Gemini ثابتًا:

```json
{
  "markScheme": {
    "point1": "معيار الدرجة الأولى",
    "point2": "معيار الدرجة الثانية أو نص فارغ",
    "point3": "معيار الدرجة الثالثة أو نص فارغ",
    "point4": "معيار الدرجة الرابعة أو نص فارغ"
  }
}
```

- تُملأ أول `marks` خانات فقط.
- تكون الخانات الزائدة سلاسل فارغة.
- يحول الخادم الخانات المستخدمة إلى المصفوفة القديمة التي تتوقعها الواجهة.
- بقي دعم المصفوفة القديمة مؤقتًا للتوافق الخلفي.
- لا يُقبل سؤال متعدد الدرجات إذا كانت إحدى نقاطه المطلوبة فارغة.

## النطاق

التعديل محصور في عقد إخراج Gemini والتحقق الخادمي. لم تتغير:

- واجهة واثق.
- محرك SVG.
- الفهرسة.
- قاعدة البيانات.
- أسرار Supabase.
- المسودات المكتملة سابقًا.
