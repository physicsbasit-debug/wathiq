# ملخص تاريخ واثق
## v0.0.68 — D4 End-to-End Repair + Progressive 2D

كشف الاختبار الحي بعد v0.0.67 أن رقم الإصدار وصل إلى GitHub بينما بقيت بعض الملفات الداخلية الحرجة على منطق أقدم؛ لذلك لم تكن مشكلة الصور أو ربط الأسئلة مجرد عيب واجهة. أعيد تطبيق التغييرات على المسار الفعلي End-to-End: retry متدرج وتعريب لأخطاء Gemini المؤقتة، Evidence Anchor بدل المطابقة الحرفية لعنوان الدرس، تشغيل مهام 2D فور اكتمال كل مفردة مع معالجة سباق المزامنة، ومنع line-art كبديل نهائي في مرئيات الكهرباء الساكنة المؤهلة للأصل 2D. التمثيلات المنظمة الدقيقة مثل الرسوم البيانية والجداول والتدريجات تبقى حتمية.


هذه الوثيقة تلخص المحطات المعمارية المهمة فقط. التفاصيل القديمة تبقى محفوظة في Git history بدل إبقاء عشرات تقارير المراحل في الشجرة الحالية.

## Phase 0 — المصادر والفهرسة

تأسست هوية المصادر، رفع الملفات، Google Drive، استخراج PDF/OCR، وبنية الصفحات والمقاطع وشجرة الكتاب.

## Phase 1 — الاختبار الموثق

أضيفت سياسة تقويم العلوم، اختيار الدروس، الاسترجاع المقيد بالمصدر والصفحات، توليد الأسئلة المرتبط بالأدلة، نموذج التصحيح، الرسوم الحتمية، التجميع والاعتماد والتصدير.

## Phase 2-A/B — سلامة الاختبار والاستئناف

تطور توليد الاختبار الكامل، وتطبيع الحسابات والمرئيات، وحماية المسودة والاستئناف وعدم فقد الخطة والأسئلة الموجودة.

## Phase 2-C — النموذج العلمي والمرئيات الدائمة

أضيفت الصور 2D الدائمة، ثم أصبح الخادم مالكًا للعقد العلمي والسياق ونمط السؤال والمرئي الضروري، مع عقود حتمية لمسائل علمية محددة ومنع التناقض بين النص والرسم والإجابة.

## Phase 2-D — التوليد التدريجي الدائم

- **D1:** نواة مشتركة للعقود والبصمات والتطبيع والتحقق.
- **D2:** دورات ومهام توليد دائمة مع leases وheartbeat والاستعادة ومنع النتائج القديمة.
- **D3:** عامل مستقل لمفردة واحدة يثبت المصدر والعقد ويستدعي Gemini لحقول المحتوى فقط.
- **D4:** ربط الواجهة بالدورة الدائمة، تشغيل مفردتين بالتوازي، حفظ النتائج تدريجيًا، الاستكمال بعد Refresh وإعادة المفردة الفاشلة وحدها.

## Phase 3-0 — بوابة قبول D4

أضيف فحص جاهزية محلي لمسار D4 ووثيقة قبول حي مستقلة. الفحص المحلي يثبت العقود والبنية فقط؛ إعلان `D4 live-stable` يبقى معلقًا حتى نجاح دورة فعلية على Supabase/Gemini. لا توجد في Phase 3-0 تغييرات على منطق الإنتاج.


## Phase 3 — الدفعة الأولى: موثوقية التوليد والمرئيات 2D

- أضيف retry داخلي متدرج مع jitter لأخطاء Gemini المؤقتة 408/429/502/503/504، مع الحفاظ على retry الدائم للمفردة.
- لم تعد الواجهة تعرض رسالة مزود Gemini الإنجليزية لأخطاء الضغط المؤقتة، بل رسالة عربية توضح أن المفردات المكتملة محفوظة.
- الأنواع المرئية التي تتطلب أصلًا علميًا 2D لا تعرض الرسم الخطي الحتمي كبديل نهائي أثناء الانتظار أو الفشل.
- شُدد فحص أصل 2D ليشمل العلاقات المكانية، عدم التناقض العلمي، وعدم إضافة عناصر علمية غير مطلوبة، مع فحص عقد علمي قبل طلب الصورة للأنماط المدعومة.
- التمثيلات العددية/البيانية المنظمة التي تكون دقتها الحتمية جزءًا من السؤال تبقى تحت ملكية واثق ولا تتحول إلى صورة حرة.

## Phase 3 — التوليد التدريجي للأصل 2D وصلابة ربط المصدر

- أصبحت مهام الأصل العلمي 2D تبدأ فور اكتمال المفردة الجاهزة بدل انتظار نجاح جميع مفردات الاختبار.
- عند استئناف مسودة غير مكتملة، يستأنف واثق الأسئلة المتبقية وفي الوقت نفسه ينشئ/يستعيد مهام 2D للمفردات المكتملة.
- أُغلق الباب الخلفي الذي كان يسمح لمخطط الكهرباء الساكنة بالعودة إلى الرسم الخطي إذا صُنفت مهارة المفردة `calculate`; الأصل 2D يبقى إلزاميًا لهذا النمط.
- استبدل حارس المطابقة الحرفية مع عنوان الدرس بربط Evidence Anchor يعتمد دعم محتوى السؤال داخل مقطع المصدر المرتبط بعقد المفردة، لتجنب الرفض الكاذب بسبب الصيغ الصرفية العربية.
- بقيت النتيجة العلمية الحتمية والوحدات والعقد العلمي حراسًا مستقلين؛ لم يُخفف التحقق العلمي من الإجابة.
