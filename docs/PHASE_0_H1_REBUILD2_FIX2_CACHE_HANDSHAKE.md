# Phase 0-H1 Rebuild 2 Fix 2 — Cache Handshake

## المشكلة المثبتة

سجل Edge Function أظهر `request_started` ثم `cache_hit` فورًا، بينما ظل طلب المتصفح معلقًا حتى مهلة 110 ثوانٍ. كان فحص الكاش داخل طلب `POST` الحامل لصورة الصفحة، فكانت الدالة تعيد النتيجة قبل استهلاك جسم الطلب.

## الإصلاح

1. إضافة `GET /ocr-layout-page?sourceId=...&pageNumber=...` لفحص الكاش بلا جسم طلب.
2. فحص الكاش قبل رسم صفحة PDF وقبل إنشاء JPEG.
3. رفع الصورة عبر `POST` فقط عند غياب الكاش.
4. استهلاك جسم `POST` قبل أي فحص كاش احتياطي أو استجابة مبكرة.
5. إضافة `Cache-Control: no-store` للاستجابات المصادق عليها.
6. الحفاظ على مهلات Fix 1 وإصلاح نوع معرفات Drive.

## معايير القبول

- وجود الكاش لا يستدعي رسم الصفحة أو رفع صورة.
- غياب الكاش يرسم ويرفع الصفحة مرة واحدة.
- مسار POST يقرأ الجسم قبل فحص الكاش.
- المرجع الذهبي: 11 وحدة و29 درسًا.
- لا SQL جديد ولا تعديل على `pages.yml`.
