# التشغيل واختبار القبول

## الفحص المحلي

```bash
npm install --no-audit --no-fund
npm run repo:check
npm run check
```

ثم عند الحاجة إلى المعاينة:

```bash
npm run dev
```

## بوابة قبول D4 الحية

هذه البوابة تسبق أي توسع معماري جديد في Phase 3.

أنشئ اختبارًا جديدًا أو استخدم مسودة غير مكتملة وتحقق من الآتي:

1. بعد بناء الخطة والضغط على التالي تظهر صفحة التقدم فورًا.
2. تعرض الواجهة أعداد المكتمل والنشط والمنتظر والمتعذر.
3. لا تعمل أكثر من مفردتين بالتوازي افتراضيًا.
4. تظهر أول مفردة مكتملة قبل انتهاء بقية الاختبار.
5. تحديث الصفحة أثناء التشغيل لا يفقد المفردات الجاهزة.
6. فتح المسودة بعد التحديث يستكمل المنتظر فقط.
7. إعادة المحاولة تعيد المفردة المتعذرة وحدها.
8. لا تعاد المفردات المكتملة ولا تتغير نتائجها بسبب Retry لمفردة أخرى.
9. بعد اكتمال المحتوى تبدأ الأصول البصرية المطلوبة بوصفها مرحلة لاحقة.
10. لا يسمح بالاعتماد أو التصدير إذا كانت أصول إلزامية غير جاهزة.
11. الاعتماد النهائي يعمل بعد اكتمال بوابات الجودة.
12. Word يعمل ويحتوي المحتوى والرسوم المطلوبة.
13. PDF يعمل ويطابق الاختبار المعتمد.

## عند الفشل

سجل قبل إنشاء دورة جديدة:

- نص الخطأ كاملًا.
- رمز الخطأ/التتبع إن ظهر.
- حالة المفردات في لوحة التقدم.
- أي مفردة كانت `ready` قبل الفشل.
- هل حدث Refresh أو Retry أو Cancel قبل المشكلة.

لا تمسح المسودة أو تنشئ دورة بديلة قبل حفظ هذه الأدلة؛ الهدف من المسار الدائم أن يجعل الفشل قابلًا للتشخيص.

## بوابة D4 قبل Phase 3

قبل أي توسع معماري جديد شغّل:

```bash
npm run d4:check
npm run check
```

ثم نفّذ اختبار القبول الحي الموثق في `docs/D4_LIVE_ACCEPTANCE.md`. لا تُعلن D4 مستقرة حيًا قبل نجاح البنود الموثقة هناك.
