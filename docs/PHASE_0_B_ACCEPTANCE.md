# Phase 0-B — معايير القبول

## الهدف

إثبات أن المعلم يستطيع الانتقال من الصفحة الرئيسية إلى معاينة اختبار كامل عبر أربع خطوات واضحة، دون رؤية تعقيدات المصادر أو الذكاء الاصطناعي.

## النطاق المنفذ

1. الصفحة الرئيسية.
2. إنشاء اختبار جديد.
3. اختيار المحتوى.
4. إعداد الاختبار.
5. خطة الاختبار وثلاثة مقترحات لكل مفردة.
6. المراجعة والمعاينة.
7. صفحة اختباراتي.
8. هيكل لوحة إدارة المحتوى.
9. حفظ تلقائي محلي.
10. تصميم RTL ومتجاوب.

## معايير النجاح

- [x] نقطة البدء واضحة فورًا.
- [x] أربع خطوات فقط في المسار الأساسي.
- [x] الرجوع إلى الخطوة السابقة لا يمسح المدخلات.
- [x] الحفظ التلقائي يعمل محليًا.
- [x] الخطأ يظهر داخل خطوة الإعداد مع سبب واضح.
- [x] يوجد اقتراح بديل لتوزيع الأسئلة عند اختلاف الدرجات.
- [x] ثلاثة بدائل لكل مفردة.
- [x] إعادة توليد مفردة واحدة فقط.
- [x] لا توجد ادعاءات بأن الذكاء الاصطناعي أو التصدير الحقيقي يعملان.
- [x] معاينة القالب تستخدم «وزارة التعليم».
- [x] واجهة الهاتف تحتفظ بالخطوات الأساسية.
- [x] TypeScript strict ينجح.
- [x] اختبارات المجال المحلية تنجح.

## خارج المرحلة

كل تكامل خارجي أو منطق إنتاجي حقيقي مؤجل إلى مراحل مستقلة.
