# Phase 1-B — معايير القبول

## الواجهة

- لا تظهر أي صياغات تجريبية قبل الاتصال بخدمة التوليد.
- الضغط على «التالي» في خطوة الإعداد يشغّل التوليد الحقيقي ويمنع النقر المتكرر أثناء الانتظار.
- لا ينتقل المستخدم إلى اختيار الأسئلة عند فشل التوليد.
- تظهر ثلاثة بدائل لكل مفردة مع الإجابة وسببها ودليل المصدر.
- سؤال الاختيار من متعدد يعرض أربعة خيارات.
- يمكن إعادة توليد مفردة واحدة دون تغيير بقية الخطة.
- تعرض المعاينة مرجع الصفحة لكل سؤال ونموذج الإجابة في اللوحة الجانبية.

## السلامة

- لا يوجد `OPENAI_API_KEY` في ملفات الواجهة أو `runtime-config.js`.
- تتطلب Edge Function رمز جلسة Supabase صالحًا.
- لا تقبل الوظيفة أكثر من 15 مفردة أو 6 مراجع.
- لا تقبل سؤال اختيار من متعدد بإجابة غير موجودة ضمن الخيارات.
- لا تقبل دليل مصدر غير موجود في نص المرجع.
- تعاد مسودات Phase 1-A القديمة إلى خطوة الإعداد قبل متابعة العمل.

## الفحص الآلي

- نجاح بناء TypeScript.
- نجاح اختبارات المجال والتخزين والاسترجاع السابقة.
- نجاح اختبارات طلب التوليد والتحقق والاتصال بالوظيفة.
- نجاح اختبار ثابت لوجود Edge Function ومخطط JSON والمصادقة.
