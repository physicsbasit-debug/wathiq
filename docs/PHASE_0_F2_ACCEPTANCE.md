# Phase 0-F2 — معايير القبول

## الهدف

رفع مصدر PDF فعليًا من لوحة واثق إلى Google Drive، وحفظ بياناته المنظمة في Supabase، دون بدء قراءة محتوى الملف أو فهرسته.

## معايير القبول الوظيفية

- [ ] لا يسمح النموذج إلا بملف PDF صالح وغير فارغ.
- [ ] يمنع الملف الذي يتجاوز 500 ميجابايت.
- [ ] يحسب واثق بصمة محتوى قبل بدء الرفع.
- [ ] يمنع رفع المحتوى نفسه مرة ثانية داخل حساب المالك.
- [ ] ينشئ مجلدات الصف والمادة ونوع المصدر عند الحاجة فقط.
- [ ] يرفع الملف إلى المسار الصحيح بحسب جهة المصدر والصف والمادة والنوع.
- [ ] يظهر تقدم الرفع بصورة واضحة.
- [ ] يمكن استكمال الرفع المتوقف باختيار الملف نفسه.
- [ ] لا يمسح سجل الجلسة المحلية إذا فشل إلغاء الجلسة مركزيًا.
- [ ] يسجل معرف ملف Drive ورابطه وحجمه ومجلده وحالة الرفع في Supabase.
- [ ] يبقى المصدر ظاهرًا بعد تحديث الصفحة وتسجيل الخروج والدخول.
- [ ] يفتح رابط الملف المرفوع في Google Drive.
- [ ] تنقل الأرشفة الملف إلى `99_أرشيف_الإصدارات` دون حذفه.
- [ ] تعيد الاستعادة الملف إلى مجلده الأصلي.
- [ ] لا تُرفع روابط المواقع العالمية كملفات.

## معايير السلامة

- [ ] لا يصل رابط جلسة Google القابل للاستكمال إلى جدول يقرأه المتصفح.
- [ ] جدول جلسات الرفع متاح لـ`service_role` فقط.
- [ ] جميع مسارات Edge Function، ما عدا OAuth callback، تتحقق من جلسة مالك المنصة.
- [ ] لا يُضاف أي Secret إلى GitHub Pages.
- [ ] تبقى صلاحية Google هي `drive.file`.

## معايير الفحص

- [ ] TypeScript strict ناجح.
- [ ] Build ناجح.
- [ ] جميع الاختبارات ناجحة.
- [ ] فحص صياغة Edge Function ناجح.
- [ ] رفع الملفات المعدلة فوق آخر نقطة استقرار ناجح.
