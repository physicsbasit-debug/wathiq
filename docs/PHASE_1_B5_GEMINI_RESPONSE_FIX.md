# Phase 1-B5 — إصلاح قراءة استجابة Gemini

## الهدف

إغلاق خطأ `JSON غير صالح أو مبتور` في دفعات توليد الأسئلة دون تغيير الفهرسة أو قوالب التقويم أو قاعدة البيانات.

## التعديلات

- جمع جميع أجزاء النص داخل كل خطوات `model_output` بالتسلسل بدل أخذ أول جزء فقط.
- التحقق من حالة التفاعل: `completed`، `incomplete`، `budget_exceeded`، `failed`، `cancelled` وغيرها.
- قراءة خطأ خطوة `model_output` عند غياب النص.
- إزالة معامل `temperature` غير المدرج في إعدادات Interactions API الحالية.
- تحليل JSON مباشرة أولًا، ثم إزالة أغلفة Markdown، ثم استخراج أول كائن JSON متوازن مع احترام الأقواس داخل السلاسل.
- إعادة محاولة الدفعة نفسها مرة واحدة عند النقص أو البتر.
- إنشاء رمز تتبع مثل `WQ-A1B2C3D4` وإظهاره للمستخدم عند الخطأ.
- تسجيل المراحل والأعداد والمدة وطول الناتج فقط، دون تسجيل مفتاح Gemini أو نصوص الكتاب.

## النشر

بعد دمج الفرع، يُنسخ ملف `supabase/functions/generate-source-questions/index.ts` عبر Raw إلى محرر الوظيفة الحالية في Supabase، ثم تضغط `Deploy function`. لا يوجد SQL ولا أسرار جديدة.
