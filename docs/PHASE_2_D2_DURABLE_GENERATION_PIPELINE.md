# Phase 2-D2 — Durable Generation Pipeline

## 1. الهدف

بناء طبقة دائمة وآمنة لدورات توليد الاختبارات ومهام المفردات، قبل ربط عامل Gemini أو واجهة الإنتاج.

هذه المرحلة لا تولد سؤالًا ولا تغيّر تجربة المستخدم الحالية. وظيفتها أن تجعل التوليد القادم قابلًا للحفظ والاستعادة ومنع التكرار والنتائج المتأخرة.

## 2. الحدود المعمارية

### داخل المرحلة

- دورة توليد مستقلة لكل مسودة وإزاحة.
- مهمة مستقلة لكل مفردة.
- بصمات الخطة والمصادر والعقود.
- منع إنشاء الدورة نفسها مرتين.
- إبطال الدورات القديمة عند إنشاء دورة أحدث.
- حجز ذري للمهمة مع `lease_token`.
- نبض وتمديد للحجز.
- استعادة المهام التي انقطع عاملها.
- منع العامل القديم أو النتيجة المتأخرة من الكتابة.
- فصل محاولات النقل عن محاولات المحتوى.
- إلغاء الدورة واستئنافها وإعادة المفردة الفاشلة.
- قراءة حالة الدورة عبر Edge Function مصادق عليها.

### خارج المرحلة

- استدعاء Gemini.
- قراءة نص المقطع من `source_chunks`.
- بناء حزمة الدليل.
- التطبيع العلمي ونموذج التصحيح النهائي.
- تشغيل عامل المفردة في الخلفية.
- ربط الواجهة وحفظ النتائج داخل المسودة.
- المنهي العام للاختبار.

تنتقل هذه المسؤوليات إلى Phase 2-D3 وما بعدها.

## 3. مخطط البيانات

### `assessment_generation_runs`

يمثل دورة واحدة لمخطط اختبار محدد، ويخزن:

- المالك والمسودة.
- `generation_epoch`.
- `plan_hash` و`source_snapshot_hash`.
- المخطط الحتمي.
- الحالة والعدادات.
- أوقات البدء والانتهاء.

لا يسمح بأكثر من دورة لنفس:

```text
owner_id + draft_id + generation_epoch
```

### `assessment_generation_items`

يمثل مهمة مفردة واحدة، ويخزن:

- هوية الدورة والمالك والمسودة والإزاحة.
- `plan_item_id` وترتيب المفردة.
- `contract_hash`.
- `source_id` و`chunk_index` و`source_content_hash`.
- عقد المفردة.
- حالة التنفيذ والمحاولات.
- العامل والحجز والنبض.
- النتيجة ومرساة الدليل وقياسات الزمن.

لا يخزن نص الكتاب أو محتوى المقطع الكامل.

## 4. قيود النزاهة

- علاقة مركبة تربط المهمة بالدورة نفسها عبر:

```text
run_id + owner_id + draft_id + generation_epoch + plan_hash
```

وبذلك لا يمكن إدخال مهمة تخص مالكًا أو مسودة أو خطة مختلفة تحت دورة أخرى.

- ترتيب المفردة فريد داخل الدورة.
- معرف المفردة فريد داخل الدورة والإزاحة.
- العامل والحجز إلزاميان فقط أثناء مراحل المعالجة.
- النتيجة إلزامية عند حالة `ready`.
- العقود والمخطط يطابقان الحقول الخادمية الأساسية عبر قيود قاعدة البيانات.

## 5. منع التكرار والنتائج القديمة

### منع التكرار

تستخدم عملية الإدخال قفلًا استشاريًا على المالك والمسودة. إذا تكرر الطلب نفسه بالإزاحة والبصمات نفسها، تعاد الدورة الموجودة بدل إنشاء دورة جديدة.

إذا أعيد استخدام الإزاحة نفسها مع خطة أو مصادر مختلفة، يرفض الطلب بتعارض صريح.

### منع النتائج القديمة

لا تقبل النتيجة إلا عند تطابق جميع الآتي:

- معرف المهمة.
- العامل.
- رمز الحجز.
- صلاحية الحجز الزمنية.
- `generation_epoch`.
- `contract_hash`.
- خطة الدورة.
- كون الدورة غير ملغاة أو مبطلة.

أي عامل قديم أو استجابة متأخرة تحصل على `false` دون كتابة.

## 6. الحجز والنبض والاستعادة

تنتقل المهمة بين:

```text
queued / retry_pending
→ grounding
→ generating
→ normalizing
→ validating
→ ready
```

الحجز يرفع `attempt_count` ويمنح العامل `lease_token` ووقت انتهاء.

النبض يسمح فقط بالانتقال القانوني بين مراحل المعالجة. الانتقالات الداخلية لا تعيد تجميع عدادات الدورة في كل نبضة، لتجنب مسح الجدول بلا فائدة.

عند انتهاء الحجز:

- تعاد المهمة إلى `retry_pending` إذا بقيت محاولة.
- تتحول إلى `failed` إذا استنفدت المحاولات.
- يمسح العامل والحجز القديمان.

## 7. سياسة المحاولات

- الحد الأقصى الافتراضي: 3 محاولات للمفردة.
- محاولة نقل إضافية واحدة فقط.
- محاولة محتوى إضافية واحدة فقط.
- الخطأ غير القابل للمحاولة ينتهي مباشرة إلى `failed`.
- المفردة `ready` لا تدخل إعادة المحاولة.

## 8. الأمان

- RLS مفعّل ومفروض على الجدولين.
- لا توجد سياسات وصول مباشرة للمتصفح.
- سحبت صلاحيات `anon` و`authenticated` و`PUBLIC` من الجداول والدوال.
- الوصول الخادمي فقط عبر `service_role`.
- Edge Function تتحقق يدويًا من رمز المستخدم بواسطة `auth.getUser` ثم تقيد كل عملية بـ`owner_id`.
- لا يخزن رمز الجلسة داخل المهمة.
- لا تمرر الوظيفة مفتاح الخدمة إلى المتصفح.

## 9. Edge Function

الوظيفة الجديدة:

```text
assessment-generation-jobs
```

تدعم فقط:

- `enqueue`
- `list`
- `retry`
- `cancel`
- `resume`

قبل الإدخال تعيد حساب:

- بصمة الخطة.
- بصمة المصادر.
- بصمة كل عقد.

كما ترفض الحقول الزائدة ونصوص المصدر المضمنة والعقود غير المطابقة للمخطط.

لا تستدعي Gemini ولا المحرك السابق.

## 10. طبقة العميل

أضيفت `AssessmentGenerationJobService` كطبقة غير موصولة بالواجهة بعد، وتوفر:

- إنشاء الدورة.
- قراءة أحدث دورة أو دورة محددة.
- إعادة مفردة فاشلة.
- إلغاء الدورة.
- استئناف الدورة.

وتتحقق من شكل الحالة والعدادات والنتائج قبل إعادتها إلى التطبيق.

## 11. اختبار القبول بعد النشر

الملف:

```text
supabase/phase_2_d2_post_deploy_acceptance.sql
```

ينفذ داخل معاملة ثم `ROLLBACK`، ويتحقق من:

- وجود الجداول.
- فرض RLS وسحب صلاحيات المتصفح.
- صلاحيات RPC.
- الإدخال المتكرر الآمن.
- إنشاء مهمتين بالعدد الصحيح.
- الحجز الذري.
- انتقالات النبض.
- رفض رمز حجز خاطئ.
- قبول النتيجة الصحيحة مرة واحدة.
- رفض النتيجة المكررة المتأخرة.
- استعادة الحجز المنتهي.
- حد محاولة النقل.
- تجميع حالة الدورة.
- الإلغاء.

يتطلب وجود مستخدم واحد على الأقل في `auth.users`، ولا يترك بيانات تجريبية.

## 12. معيار الانتقال إلى Phase 2-D3

1. GitHub Actions خضراء.
2. تنفيذ migration بنجاح.
3. نشر `assessment-generation-jobs`.
4. ظهور PASS من اختبار القبول بعد النشر.
5. عدم وجود أثر على واجهة الإنتاج الحالية.
