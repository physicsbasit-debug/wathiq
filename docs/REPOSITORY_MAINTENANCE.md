# صيانة المستودع

## ما يبقى في `main`

- كود المصدر.
- اختبارات الانحدار الحالية.
- ملفات SQL وEdge Functions اللازمة لتشغيل أو إعادة إنشاء البيئة.
- workflows الحقيقية داخل `.github/workflows/`.
- المراجع الرسمية اللازمة للمشروع.
- وثائق التشغيل والمعمارية الحالية فقط.

## ما لا يبقى في `main`

- `dist/` أو أي نواتج بناء.
- ZIPs أو نسخ احتياطية.
- تقارير اختبار مرحلية منتهية.
- `CHANGED_FILES_MANIFEST_PHASE_*`.
- تعليمات رفع خاصة بمرحلة منتهية.
- نسخ ظاهرة مكررة من `.github`.
- ملفات مؤقتة مثل `*~`, `.bak`, `.tmp`.

Git history هو الأرشيف الطبيعي للوثائق والتقارير القديمة.

## فحص النظافة

```bash
npm run repo:check
```

يفحص الجذر والوثائق ويمنع عودة الأنماط القديمة، ويتحقق من أن `dist/` غير متتبع عندما يكون التشغيل داخل Git repository.

## قبل أي Merge

```bash
npm run repo:check
npm run check
```

ولا تُدمج مرحلة إذا فشل أحدهما.

## GitHub Actions

يوجد Workflow باسم `Repository Maintenance` داخل:

```text
.github/workflows/repository-maintenance.yml
```

يمكن تشغيله يدويًا من تبويب **Actions**. كما يعمل تلقائيًا عند تعديل Workflow الصيانة أو حارس النظافة أو وثيقة الصيانة نفسها.

تسلسل العمل:

1. يحذف فقط الأنماط القديمة المعروفة مثل نواتج `dist/` وتقارير `PHASE_*` والـZIPs والنسخ المؤقتة في الجذر.
2. يثبت الاعتماديات عبر `npm install --no-package-lock --no-audit --no-fund` بما يطابق بنية المستودع الحالية التي لا تتتبع lockfile.
3. يشغّل `npm run repo:check`.
4. يشغّل مجموعة الاختبارات الكاملة عبر `npm run check`.
5. إذا نتج حذف حقيقي، ينشئ GitHub Actions commit صيانة تلقائيًا إلى `main`.

لا يحذف Workflow ملفات مصدر أو اختبارات أو SQL أو Edge Functions لمجرد أنها غير معروفة؛ الحذف الآلي محصور في الأنماط القديمة المحددة صراحة في حارس النظافة.

## أوامر الحراسة الحالية

- `npm run repo:check`: يتحقق من نظافة شجرة المستودع.
- `npm run repo:clean`: يزيل فقط المخلفات المعروفة ثم يمكن إعادة الفحص.
- `npm run d4:check`: يفحص جاهزية مسار D4 المحلي قبل القبول الحي.
