# معايير قبول Phase 0-F1

## النطاق

ربط Google Drive بحساب مالك المنصة وإنشاء هيكل المجلدات الأساسي فقط.

## القبول الوظيفي

- [ ] لا يظهر زر الربط قبل تسجيل دخول مالك المنصة.
- [ ] يبدأ زر الربط OAuth من Google.
- [ ] يعود المستخدم إلى رابط واثق بعد الموافقة.
- [ ] تبقى حالة الاتصال بعد تحديث الصفحة.
- [ ] يُنشأ مجلد `واثق` في Drive.
- [ ] تُنشأ المجلدات الأساسية التابعة له.
- [ ] إعادة التحقق لا تنشئ مجلدات مكررة.
- [ ] زر فتح المجلد يفتح مجلد واثق الصحيح.
- [ ] فصل الاتصال لا يحذف المجلدات أو الملفات.
- [ ] إلغاء موافقة Google يعرض رسالة واضحة دون كسر سجل المصادر.

## القبول الأمني

- [ ] Google Client Secret غير موجود في ملفات GitHub أو runtime-config.
- [ ] Refresh Token لا يصل إلى المتصفح.
- [ ] جداول الرموز لا تسمح بوصول `anon` أو `authenticated` مباشرة.
- [ ] المسارات المحمية تتحقق من Supabase user JWT.
- [ ] callback يتحقق من state أحادي الاستخدام ومحدد المهلة.
- [ ] النطاق المطلوب هو `drive.file` فقط.

## القبول التقني

- [ ] GitHub Actions أخضر.
- [ ] TypeScript strict ناجح.
- [ ] جميع الاختبارات ناجحة.
- [ ] GitHub Pages يقرأ `WATHIQ_GOOGLE_OAUTH_CLIENT_ID`.
- [ ] Edge Function منشورة باسم `google-drive-oauth`.
- [ ] SQL المرحلة نُفّذ بنجاح.

## خارج النطاق

- رفع PDF.
- قراءة PDF أو OCR.
- إنشاء مجلدات الصفوف والمواد.
- حفظ بيانات ملفات Drive داخل سجل المصادر.
- الأرشفة الفعلية للملفات.
