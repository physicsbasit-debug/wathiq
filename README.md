# واثق

**واثق** مولد اختبارات عربي بالكامل لمواد **علوم كامبريدج**. لا يحتاج المستخدم إلى رفع كتاب أو دليل أو بناء مكتبة مصادر قبل البدء: اختر **الصف / المرحلة** ثم **المادة** ثم **الموضوع من قائمة المنهج**، ويبدأ التأليف.

> **اسم الموضوع يكفي. حرية عالية في التأليف، صرامة عالية في المراجعة العلمية، وعربية كاملة من اليمين إلى اليسار.**

- الإصدار الحالي: **0.3.19 — Server-Owned 2D Visual Jobs**.
- النطاق: **مواد العلوم فقط**.
- Cambridge Primary Science **0097**: المراحل **1–6**.
- Cambridge Lower Secondary Science **0893**: المراحل **7–9**.
- Cambridge IGCSE: الفيزياء **0625**، الكيمياء **0620**، الأحياء **0610**، العلوم المجمعة **0653**، العلوم المنسقة **0654**.

## 0.3.19 — Server-Owned 2D Visual Jobs

- لم يعد إنشاء مهمة صورة `context_scene` يعتمد على مؤقت المتصفح بعد اكتمال السؤال؛ `assessment-generation-worker` يضمن إنشاء Visual Job دائمة خادميًا **قبل** اعتماد المفردة `ready`.
- إذا تعذرت خدمة `question-visual-jobs` أو أعادت `jobs=[]`، تبقى المفردة في `retry_pending` بدل الظهور كسؤال مكتمل بلا صورة.
- `VisualJobService` في العميل أصبح يرفض الاستجابة الناقصة صراحة، والعميل بقي طبقة مزامنة/استعادة فقط.
- توقيع الإنشاء التلقائي أصبح مرتبطًا بمعرف المسودة ويُصفّر عند إبطال التوليد لمنع قفل مزامنة من اختبار سابق.
- لا SQL ولا Secret جديد. النشر يحتاج `assessment-generation-worker` و`question-visual-jobs` فقط؛ `science-visual-generation` لا يتغير في هذه الدفعة.

## 0.3.18 — 2D Visual Reset

- اقتُلع مولد الرسوم التخطيطية الخطية القديم للمشاهد العلمية (`force/circuit/electrostatic/ray/pressure/flow/instrument-scale`) من مسار الإنتاج.
- كل مرئي علمي غير رقمي أصبح `illustration_2d` ثم `context_scene`: أصل 2D تعليمي كامل يولد في `science-visual-generation` ويخضع لمراجعة علمية وبصرية مستقلة قبل اعتماده.
- تبقى `data_table` و`line_graph` و`bar_chart` حتمية داخل واثق لأن الأرقام والمحاور والبيانات يجب ألا تُفوض إلى مولد صور حر.
- Visual Planner لم يعد يرى الإجابة أو نموذج التصحيح؛ بالنسبة للجداول والرسوم البيانية يرى فقط معلومات الطالب الظاهرة، وتضيف مراجعة الصورة بوابة `noAnswerLeakage`.
- المسودات القديمة ذات الأنواع التخطيطية تُقرأ عبر جسر ترحيل فقط وتتحول إلى `context_scene`؛ لا يعاد تشغيل هندستها القديمة.
- لا SQL ولا Secret جديد. يتطلب النشر إعادة `assessment-generation-worker` و`science-visual-generation` فقط.

## 0.3.17 — Adaptive Parallel Generation

- يبقى أول سؤال وحده بوابة تشغيل حقيقية للمزود كما في 0.3.15.
- بعد أول `ready` يشغّل واثق **مفردتين بالتوازي** بدل إبقاء الاختبار كله على `concurrency=1`.
- عند 429/503/timeout أو ضغط مماثل يهبط المنسق مؤقتًا إلى مسار واحد، ثم يستعيد التوازي تلقائيًا بعد زوال إشارة الضغط.
- لا تغيير في Author/Reviewer أو معايير الجودة أو SQL أو Edge Functions أو Secrets.
- الهدف تقليل زمن الاختبار الكلي دون اختصار المراجعة العلمية أو زيادة التوازي إلى مستوى عدواني.

## 0.3.16 — Recovery Baseline Reconciliation

أعاد هذا الإصدار خط التشغيل الكامل الذي انحرف بعد 0.3.15: واجهة اختيار الصف/المادة/الموضوع، بناء Blueprint v4 وعقود المفردات، الاستئناف الدائم، مزامنة المرئيات، المراجعة، وWord/PDF. لم يُعَد بناء Durable Generation ولم يُغيَّر Runtime Contract أو Provider Protocol؛ أساس التشغيل ما زال 0.3.15 مع `providerProtocolVersion=5`.

أضيف `runtime:check` كحارس مستقل يمنع الأنماط التي سببت الانحدار نفسه: `@ts-nocheck` في runtime، استيرادات `import type {}` الفارغة لإرضاء فحص reachability، stubs تعيد `{}`/`[]` بدل Blueprint حقيقي، placeholders بصرية، وتحويل فحوص التصدير إلى no-op. هذه المرحلة **استعادة خط أساس** وليست مرحلة تحسين جودة الأسئلة؛ تحسينات Learning Objective Card وVisual Assessment Integrity تأتي بعد إثبات القبول الحي.

## إصلاح 0.3.15 — Durable First-Item Provider Gate

أثبت فحص End-to-End للنسخة المنشورة أن وظائف Supabase الأربع كانت مطابقة حرفيًا للمستودع، وأن الانقطاع الحالي يحدث قبل `enqueue`: الواجهة كانت تستدعي `preflight` إلزاميًا، والـWorker كان ينفذ نداءات Gemini تجريبية متسلسلة بمهلة 20 ثانية لكل نداء. أي بطء مؤقت كان يمنع إنشاء/استئناف الدورة قبل أن تصل المفردات إلى نظام `retry_pending` الدائم. في 0.3.15 أزيل أي نداء مزود من بوابة البدء؛ `health` يفحص عقد Worker وقاعدة البيانات فقط، ثم تبدأ الدورة مباشرة. أول مفردة حقيقية تعمل كبوابة مزود دائمة: تبدأ بتوازي 1، وإذا نجحت مفردة واحدة يعود التوازي الطبيعي، وإذا ظهر 429/503/timeout يؤجلها واثق داخل الدورة دون استهلاك محاولة محتوى.

## المسار الوحيد للتوليد

```text
الصف / المرحلة + مادة العلوم + موضوع كامبريدج من القائمة
  ↓
سياق كامبريدج عالمي مناسب للمستوى
  ↓
مؤلف بالذكاء الاصطناعي يعيد عقد مفردة نصيًا نحيفًا + نية مرئية فقط
  ↓
مراجع علمي وتقويمي مستقل يراجع العقد النحيف ويستطيع إعادة الصياغة
  ↓
تحقق حتمي فقط فيما يمكن إثباته
  ↓
إذا كان المرئي غير رقمي → أصل علمي 2D مدقق
وإذا كان جدولًا/رسمًا بيانيًا → Visual Planner للبيانات فقط ثم Renderer حتمي
  ↓
مراجعة الاختبار → وورد / بي دي إف
```




## عقد المفردة النحيف ومسار المرئيات الحالي

- المؤلف والمراجع يعيدان النص ونموذج التصحيح و`visualIntent` فقط؛ لا توجد هندسة خطوط/متجهات/دوائر في عقد السؤال.
- الأنواع الحالية هي: `none`, `illustration_2d`, `data_table`, `line_graph`, `bar_chart`.
- `illustration_2d` يتحول إلى `context_scene` ويُنشأ كصورة 2D علمية مدققة.
- `data_table`, `line_graph`, `bar_chart` فقط تدخل Visual Planner للبيانات ثم تُرسم حتميًا داخل واثق.
- Visual Planner للبيانات يرى نص الطالب ومثيره فقط، ولا يرى `answer` أو `markScheme`.
- لا توجد بوابة Gemini تمهيدية قبل إنشاء الدورة؛ أول مفردة حقيقية تبقى فحص المزود التشغيلي داخل المسار الدائم.

## عقد التشغيل بين قاعدة البيانات وGemini

- قبل إطلاق أي مفردة يتحقق Worker من وجود عقد قاعدة البيانات `assessment_generation_runtime_contract_v1`، لذلك لا تبدأ دورة جديدة إذا كان كود Edge أحدث من SQL المنشور.
- ضغط المزود له RPC مستقلة `defer_assessment_generation_item_v1` لا تستطيع تحويل المفردة إلى `failed`؛ فشل المحتوى له RPC مستقلة أخرى.
- استرداد العامل المتوقف يستخدم `recover_stale_assessment_generation_items_v1` ويعامل انقطاع البنية كتأجيل تشغيلي لا كمحاولة محتوى.
- رسائل 429 تستخرج تفاصيل `QuotaFailure` الآمنة عندما ترسلها Google: المقياس، معرف الحصة، الحد، والنموذج، بدل رسالة عامة لا تساعد في التشخيص.

## التحكم في ضغط التوليد والحصة

- يبدأ واثق بأول مفردة حقيقية وحدها كبوابة للمزود؛ بعد نجاح أول `ready` يعود للتوازي الطبيعي، ويخفضه إلى 1 عند ضغط المزود.
- أخطاء النقل مثل `429` و`503` والمهلة **لا تستهلك محاولة من محاولات محتوى السؤال**؛ يعيد واثق عداد المحاولة إلى حالته السابقة ويضع المفردة في `retry_pending`.
- إذا أعاد Gemini مهلة `RetryInfo` أو `Retry-After` يحفظ واثق الموعد في قاعدة البيانات ولا يعيد الإرسال قبله.
- يميز واثق بين ضغط معدل الطلب `MODEL_RATE_LIMITED` وبين استنفاد الحصة `MODEL_QUOTA_EXHAUSTED`؛ استنفاد الحصة يأخذ مهلة أطول ولا يتحول إلى فشل 3/3.
- بعد نجاح المؤلف تُحفظ **نقطة استئناف للمؤلف** قبل تشغيل المراجع. إذا تعطل المراجع بسبب الضغط، يعاد استخدام السؤال المؤلف نفسه بدل استهلاك نداء جديد لإعادة تأليفه.
- فشل المحتوى العلمي/التقويمي وحده يستهلك ميزانية محاولات المحتوى؛ أما انقطاع الخدمة فهو تأجيل تشغيلي وليس رسوبًا للمفردة.

## جدول المواصفات

للصفوف 5–10، لا يترك واثق الدرجة وعدد المفردات وتوزيع أهداف التقويم للمستخدم أو للنموذج. يشتق الخطة من **وثيقة تقويم تعلم الطلبة في مواد العلوم 2025/2026** ثم يوزع المفردات والدرجات حتميًا قبل إرسال كل مفردة إلى المؤلف الذكي.

- الاختبارات القصيرة للصفوف 5–9: 15 درجة، 40% معرفة، 40% تطبيق، 20% استدلال.
- الاختبار القصير للصف 10: 10 درجات، 2 اختيار من متعدد، مفردة طويلة، والبقية قصيرة؛ 40/40/20.
- النهائي للصفوف 5–9: 40 درجة، 25–35 مفردة رسميًا، 40/40/20 في أهداف التقويم والصعوبة.
- النهائي للصف 10: 60 درجة، 30–40 مفردة، ساعتان، 10 اختيار من متعدد، مفردتان طويلتان على الأقل، 40/40/20 في أهداف التقويم والصعوبة، و8–10 درجات للاستقصاء العلمي.
- واثق يستخدم عددًا تشغيليًا ثابتًا داخل المدى الرسمي حتى تكون الخطة قابلة للتوليد وإعادة الإنتاج بصورة حتمية.

## قواعد النواة

- لا توجد منظومة رفع مصادر أو إدارة محتوى في المنتج الحالي.
- لا Google Drive ولا OAuth ولا OCR ولا شجرة كتاب ولا فهرسة موضعية.
- لا مولدات أسئلة قديمة ولا عقود صلبة تفرض السياق أو شكل السؤال على المؤلف.
- لا أهداف تعليمية اصطناعية ولا بوابة رفض تعتمد على تطابق كلمات عنوان الدرس.
- لا مولد رسوم تخطيطية خطية ولا Overlay احتياطي؛ كل مرئي علمي غير رقمي صورة 2D مدققة.
- القرار البصري واحد: `none` أو صورة 2D علمية أو جدول/رسم بياني عددي حتمي. لا توجد مخططات خطية قديمة في مسار الإنتاج.
- ورقة الطالب لا تعرض رسائل فشل أو انتظار للأصول البصرية، ولا يظهر فيها الشرح العلمي أو ملاحظات المراجع.
- محقق علمي حتمي يمنع تناقضات فيزيائية قابلة للكشف يقينًا قبل الاعتماد، مع بقاء المراجع الذكي مسؤولًا عن الحكم العلمي الأوسع.
- الجداول والرسوم البيانية ذات القيم الدقيقة تبقى حتمية؛ تدريجات/أجهزة ومشاهد علمية غير رقمية تنتقل إلى 2D ولا تعتمد على مولد الخطوط القديم.
- لا تظهر رسالة مزود خام بالإنجليزية للمستخدم.
- الواجهة والتقارير والتصدير عربية واتجاهها من اليمين إلى اليسار.
- `npm run legacy:check` يفشل إذا عادت أحفورة محظورة.
- `npm run runtime:check` يفشل إذا تحولت النواة إلى stubs/no-op أو عادت reachability وهمية بدل ارتباط runtime حقيقي.
- `npm run ui:check` يفشل إذا كُسرت العربية أو RTL أو تسربت واجهة إنجليزية معروفة.

- عند كل إصدار جديد يجب تحديث `README.md` ليعكس رقم الإصدار الحالي وسلوكه التشغيلي الفعلي قبل تجهيز حزمة الرفع.
