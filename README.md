# واثق

منصة عربية مبسطة لإنشاء الاختبارات القصيرة في مواد العلوم.

## المرحلة الحالية

**Phase 0-E — Central Source Storage**

تنقل هذه المرحلة سجل المصادر من الاعتماد على متصفح واحد إلى سجل مركزي في Supabase، مع إبقاء نسخة محلية احتياطية. لا ترفع ملفات PDF نفسها بعد؛ الذي يُحفظ مركزيًا هو بيانات المصدر وحالته ومساره المقترح.

## ما يعمل

- تسجيل دخول مالك المنصة بالبريد وكلمة المرور.
- حفظ سجل المصادر في Supabase عبر Data API.
- حماية السجلات بسياسات Row Level Security.
- مزامنة السجل بين الأجهزة لنفس حساب المالك.
- ترحيل سجل Phase 0-D المحلي تلقائيًا بعد أول تسجيل دخول.
- حفظ نسخة محلية احتياطية عند تعذر الاتصال.
- إضافة مصدر، وتحديث حالته، والأرشفة والاستعادة مركزيًا.
- تصدير واستيراد JSON كنسخة احتياطية مستقلة.
- كشف التكرار ورقم الفهرسة وتفاصيل المصدر من Phase 0-D.
- رحلة المعلم ذات الخطوات الأربع من Phase 0-B.

## ما لا يعمل عمدًا

- لا رفع حقيقي لملفات PDF إلى Google Drive.
- لا قراءة أو فهرسة محتوى PDF.
- لا جلب محتوى المواقع.
- لا ذكاء اصطناعي حي.
- لا حسابات معلمين إنتاجية.
- لا تصدير Word أو PDF حقيقي.

## إعداد التخزين المركزي

اتبع الوثيقة:

- `docs/PHASE_0_E_SUPABASE_SETUP.md`

يعمل المشروع محليًا بصورة تلقائية إذا لم تُضبط متغيرات Supabase، فلا تنكسر المعاينة بسبب إعداد ناقص. يا لها من فكرة غريبة: النظام يعترف بأن الإعداد غير مكتمل بدل التظاهر بالاتصال.

- بناء GitHub Pages.
- اختبارات المنطق وسجل المصادر والعميل المركزي.
