# واثق — اختبارات علوم موثّقة من المصدر

## Phase 1-B7 — تثبيت الاستناد بمقاطع أدلة مرقمة

يعالج هذا الإصدار فشل الدفعات الذي كان يظهر برسالة **«تعذر إثبات استناد أحد الأسئلة إلى نص المرجع حرفيًا»** رغم نجاح Gemini في توليد بعض المفردات.

### أصل المشكلة

كان الخادم يطلب من Gemini نسخ اقتباس حر داخل الحقل `sourceSupport`، ثم يقارن الاقتباس بالنص الكامل للمرجع مقارنة حرفية بعد التطبيع. أي اختصار، حذف كلمة، أو اختيار جملة من مرجع آخر داخل الدفعة كان يؤدي إلى رفض الدفعة كاملة. هذا جعل سلامة التوليد تعتمد على النسخ الحرفي من النموذج، وهو اعتماد هش وغير ضروري.

### ما يعمل في هذا الإصدار

- تقسيم كل مرجع إلى مقاطع دليل قصيرة ومرقمة داخل الخادم.
- إرسال معرفات المقاطع المسموح بها لكل مفردة عبر `allowedEvidenceIds`.
- مطالبة Gemini بإعادة `sourceEvidenceId` فقط بدل نسخ الاقتباس بنفسه.
- تحقق الخادم من أن معرف الدليل موجود وينتمي إلى مرجع المفردة نفسها.
- إضافة نص الدليل الحقيقي إلى `sourceSupport` من الخادم، لا من ناتج Gemini.
- عدم رفض السؤال بسبب اختلافات الكتابة أو علامات الترقيم أو اختصار الاقتباس.
- وضع علامة **يحتاج تدقيقًا أدق** تلقائيًا إذا كان الارتباط اللفظي بين السؤال والدليل ضعيفًا، بدل إسقاط الدفعة كاملة.
- استمرار استخدام `generateContent` وJSON المنظم والدفعات من مفردتين.
- استمرار دعم الدروس المتعددة وقوالب التقويم الرسمية وعناوين الاختبارات وتاريخها.
- حفظ مسودة التوليد الحالية بعد تحديث الصفحة بدل إعادتها إلى الإعداد بسبب رقم إصدار قديم ثابت.

### متطلبات التشغيل

- وجود `GEMINI_API_KEY` و`WATHIQ_APP_URL` في أسرار Supabase.
- `GEMINI_MODEL` اختياري، والقيمة الافتراضية `gemini-2.5-flash`.
- إعادة نشر الوظيفة `generate-source-questions` من محرر Supabase بعد دمج التعديلات.

### الفحص

```bash
npm run check
```

لا يوجد SQL جديد، ولا حاجة إلى إعادة فهرسة المصادر الجاهزة أو تغيير مفتاح Gemini.
