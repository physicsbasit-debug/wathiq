# واثق

## Phase 0-H2 — Structured TOC Builder

توقف هذه المرحلة مسار الرفض الشامل الذي كان يحاول تحويل OCR إلى هيكل نهائي بصورة آلية. أصبحت إحداثيات Google Vision مدخلًا لمسودة مراجعة فقط، ثم يقرر مالك المنصة ما يُحفظ وما يُعتمد.

### تجربة الاستخدام

- يحدد واثق صفحة أو صفحات الفهرس تلقائيًا، أو يقبل أرقامها يدويًا.
- يعيد استخدام `layout_json` المحفوظ دون إعادة OCR عند وجوده.
- يعرض جدولًا منظمًا لكل صف: النوع، الرمز، العنوان، رقم الصفحة، ومصدر السطر.
- يمكن تغيير الصف إلى وحدة أو درس أو تجاهل، وتعديل الرمز والعنوان والصفحة، وإعادة الترتيب أو الحذف والإضافة.
- يعرض نص OCR المرجعي تحت الجدول للمقارنة بدل إخفاء ما قرأته الخدمة.
- لا يحفظ شيئًا تلقائيًا بعد OCR، ولا يحذف الهيكل السابق عند فتح مسودة جديدة.
- يفصل بين التحقق الأساسي لحفظ المسودة والتحقق الصارم قبل الاعتماد.

### التحقق قبل الاعتماد

- وجود وحدة واحدة على الأقل.
- عدم وجود درس قبل أول وحدة.
- عدم وجود وحدة بلا دروس أو عناصر تابعة.
- سلامة العناوين وأرقام الصفحات.
- تصاعد صفحات الدروس.
- كشف نقص تسلسل رموز الدروس عندما يستخدم الكتاب رموزًا رقمية.

### التوافق

- يبقى OCR الموضعي وكاش `layout_json` كما هما.
- يبقى محلل H1 القديم في المستودع للتوافق والاختبارات، لكنه لم يعد يقود مسار الواجهة.
- لا يوجد SQL جديد.
- لا تغيير في Edge Function.
- لا تغيير في `.github/workflows/pages.yml`.
