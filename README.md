# واثق

**واثق** مولد اختبارات عربي بالكامل لمواد **علوم كامبريدج**. لا يحتاج المستخدم إلى رفع كتاب أو دليل أو بناء مكتبة مصادر قبل البدء: اختر **الصف / المرحلة** ثم **المادة** ثم **الموضوع من قائمة المنهج**، ويبدأ التأليف.

> **اسم الموضوع يكفي. حرية عالية في التأليف، صرامة عالية في المراجعة العلمية، وعربية كاملة من اليمين إلى اليسار.**

- الإصدار الحالي: **0.3.14 — Local-Validated Visual Planner**.
- النطاق: **مواد العلوم فقط**.
- Cambridge Primary Science **0097**: المراحل **1–6**.
- Cambridge Lower Secondary Science **0893**: المراحل **7–9**.
- Cambridge IGCSE: الفيزياء **0625**، الكيمياء **0620**، الأحياء **0610**، العلوم المجمعة **0653**، العلوم المنسقة **0654**.

## إصلاح 0.3.14 — Local-Validated Visual Planner

أثبتت سجلات Supabase أن `preflight_visual_planner` وحده كان يعيد HTTP 400 `INVALID_ARGUMENT` بينما نجح فحص الاتصال وعقدا المؤلف والمراجع. لذلك لم يعد Visual Planner يرسل مخطط JSON Schema هندسيًا عميقًا إلى Gemini. يطلب واثق الآن JSON خفيفًا بلا `responseJsonSchema` لهذا الجزء فقط، ثم يطبّع البيانات ويفرض التحقق المحلي الحتمي قبل الاعتماد. كما أزيل مخطط المرئي الاختياري من بوابة preflight العامة، فلا يستطيع عطل في رسم اختياري منع إنشاء الاختبار كاملًا.

## المسار الوحيد للتوليد

```text
الصف / المرحلة + مادة العلوم + موضوع كامبريدج من القائمة
  ↓
سياق كامبريدج عالمي مناسب للمستوى
  ↓
مؤلف بالذكاء الاصطناعي يعيد عقد مفردة نصيًا نحيفًا + نية مرئية فقط
  ↓
مراجع علمي وتقويمي مستقل يراجع العقد النحيف ويستطيع إعادة الصياغة
  ↓
تحقق حتمي فقط فيما يمكن إثباته
  ↓
مخطط مرئي متخصص يُستدعى فقط إذا اختير مرئي علمي منظم
  ↓
Renderer حتمي للمخططات العلمية الدقيقة
أو أصل 2D مدقق للمشهد السياقي
  ↓
مراجعة الاختبار → وورد / بي دي إف
```




## عقد المفردة النحيف ومخطط المرئيات المتخصص

- المؤلف والمراجع لا يعيدان إحداثيات أو متجهات أو سلاسل بيانات أو مكونات دوائر داخل عقد السؤال الرئيسي. يعيدان النص ونموذج التصحيح و`visualIntent` فقط.
- `visualIntent` يحسم النوع والغرض باختصار: `none` أو نوع مرئي فعلي مع وصف قصير. لا توجد حصة صور مفروضة ولا طبقة `helpful/required`.
- إذا كان النوع علميًا منظمًا مثل `force_diagram` أو `circuit_diagram` أو `line_graph`، يستدعي Worker **Visual Planner** منفصلًا بمخطط JSON صغير خاص بذلك النوع وحده.
- `none` و`illustration_2d` لا يستدعيان Visual Planner المنظم؛ المشهد السياقي يظل في مسار الصور 2D الحالي.
- preflight يفحص عقد المؤلف النحيف وعقد المراجع النحيف وعينة فعلية من مخطط المرئيات المتخصص قبل بدء دورة الاختبار، حتى يظهر رفض Structured Output قبل إنشاء المفردات.

## عقد التشغيل بين قاعدة البيانات وGemini

- قبل إطلاق أي مفردة يتحقق Worker من وجود عقد قاعدة البيانات `assessment_generation_runtime_contract_v1`، لذلك لا تبدأ دورة جديدة إذا كان كود Edge أحدث من SQL المنشور.
- ضغط المزود له RPC مستقلة `defer_assessment_generation_item_v1` لا تستطيع تحويل المفردة إلى `failed`؛ فشل المحتوى له RPC مستقلة أخرى.
- استرداد العامل المتوقف يستخدم `recover_stale_assessment_generation_items_v1` ويعامل انقطاع البنية كتأجيل تشغيلي لا كمحاولة محتوى.
- رسائل 429 تستخرج تفاصيل `QuotaFailure` الآمنة عندما ترسلها Google: المقياس، معرف الحصة، الحد، والنموذج، بدل رسالة عامة لا تساعد في التشخيص.

## التحكم في ضغط التوليد والحصة

- يبدأ واثق بمفردة واحدة في كل مرة لتقليل ضغط RPM/TPM على Gemini، مع بقاء التوليد تدريجيًا وحفظ كل مفردة فور اكتمالها.
- أخطاء النقل مثل `429` و`503` والمهلة **لا تستهلك محاولة من محاولات محتوى السؤال**؛ يعيد واثق عداد المحاولة إلى حالته السابقة ويضع المفردة في `retry_pending`.
- إذا أعاد Gemini مهلة `RetryInfo` أو `Retry-After` يحفظ واثق الموعد في قاعدة البيانات ولا يعيد الإرسال قبله.
- يميز واثق بين ضغط معدل الطلب `MODEL_RATE_LIMITED` وبين استنفاد الحصة `MODEL_QUOTA_EXHAUSTED`؛ استنفاد الحصة يأخذ مهلة أطول ولا يتحول إلى فشل 3/3.
- بعد نجاح المؤلف تُحفظ **نقطة استئناف للمؤلف** قبل تشغيل المراجع. إذا تعطل المراجع بسبب الضغط، يعاد استخدام السؤال المؤلف نفسه بدل استهلاك نداء جديد لإعادة تأليفه.
- فشل المحتوى العلمي/التقويمي وحده يستهلك ميزانية محاولات المحتوى؛ أما انقطاع الخدمة فهو تأجيل تشغيلي وليس رسوبًا للمفردة.

## جدول المواصفات

للصفوف 5–10، لا يترك واثق الدرجة وعدد المفردات وتوزيع أهداف التقويم للمستخدم أو للنموذج. يشتق الخطة من **وثيقة تقويم تعلم الطلبة في مواد العلوم 2025/2026** ثم يوزع المفردات والدرجات حتميًا قبل إرسال كل مفردة إلى المؤلف الذكي.

- الاختبارات القصيرة للصفوف 5–9: 15 درجة، 40% معرفة، 40% تطبيق، 20% استدلال.
- الاختبار القصير للصف 10: 10 درجات، 2 اختيار من متعدد، مفردة طويلة، والبقية قصيرة؛ 40/40/20.
- النهائي للصفوف 5–9: 40 درجة، 25–35 مفردة رسميًا، 40/40/20 في أهداف التقويم والصعوبة.
- النهائي للصف 10: 60 درجة، 30–40 مفردة، ساعتان، 10 اختيار من متعدد، مفردتان طويلتان على الأقل، 40/40/20 في أهداف التقويم والصعوبة، و8–10 درجات للاستقصاء العلمي.
- واثق يستخدم عددًا تشغيليًا ثابتًا داخل المدى الرسمي حتى تكون الخطة قابلة للتوليد وإعادة الإنتاج بصورة حتمية.

## قواعد النواة

- لا توجد منظومة رفع مصادر أو إدارة محتوى في المنتج الحالي.
- لا Google Drive ولا OAuth ولا OCR ولا شجرة كتاب ولا فهرسة موضعية.
- لا مولدات أسئلة قديمة ولا عقود صلبة تفرض السياق أو شكل السؤال على المؤلف.
- لا أهداف تعليمية اصطناعية ولا بوابة رفض تعتمد على تطابق كلمات عنوان الدرس.
- لا رسم خطي أو Overlay احتياطي للمرئيات التوضيحية؛ المرئي المطلوب ثنائي الأبعاد ومدقق علميًا.
- القرار البصري واحد: إما `none` أو نوع مرئي فعلي. المخططات العلمية المنظمة تُرسم داخل واثق فورًا، و`context_scene` وحده يحتاج أصل صورة 2D مدققًا قبل الاعتماد والتصدير.
- ورقة الطالب لا تعرض رسائل فشل أو انتظار للأصول البصرية، ولا يظهر فيها الشرح العلمي أو ملاحظات المراجع.
- محقق علمي حتمي يمنع تناقضات فيزيائية قابلة للكشف يقينًا قبل الاعتماد، مع بقاء المراجع الذكي مسؤولًا عن الحكم العلمي الأوسع.
- الجداول والرسوم البيانية والتدريجات ذات القيم الدقيقة تبقى حتمية.
- لا تظهر رسالة مزود خام بالإنجليزية للمستخدم.
- الواجهة والتقارير والتصدير عربية واتجاهها من اليمين إلى اليسار.
- `npm run legacy:check` يفشل إذا عادت أحفورة محظورة.
- `npm run ui:check` يفشل إذا كُسرت العربية أو RTL أو تسربت واجهة إنجليزية معروفة.

## قاعدة تحديث التوثيق

- عند كل إصدار جديد يجب تحديث `README.md` ليعكس رقم الإصدار الحالي وسلوكه التشغيلي الفعلي قبل تجهيز حزمة الرفع.
- إذا تغيّر النشر أو قاعدة البيانات أو وظائف Edge، تُحدّث وثائق `DEPLOYMENT.md` و`OPERATIONS.md` و`HISTORY.md` في الإصدار نفسه.
- لا يُعتمد وصف قديم لمسار التوليد أو المرئيات أو إعادة المحاولة بعد تغيّر الكود.

## الفحص

```bash
npm install --no-package-lock --no-audit --no-fund
npm run check
```

يشمل الفحص: نظافة المستودع، منع الأحافير، العربية وRTL، بناء TypeScript، واختبارات السلوك الحالي فقط.
