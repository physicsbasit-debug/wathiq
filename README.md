# واثق

منصة عربية لإنشاء الاختبارات القصيرة في مواد العلوم اعتمادًا على مصادر مركزية معتمدة.

## المرحلة الحالية

**Phase 0-F2 — رفع ملفات PDF فعليًا إلى Google Drive**

تضيف هذه المرحلة رفع مصادر PDF من لوحة واثق إلى المجلد الصحيح في Google Drive، مع تسجيل بيانات الملف داخل Supabase، ومنع تكرار المحتوى، واستكمال الرفع المتوقف، والأرشفة والاستعادة دون حذف.

## ما يعمل في هذه المرحلة

- واجهة عربية RTL ومتجاوبة.
- سجل مصادر مركزي في Supabase.
- اتصال Google Drive المعتمد في Phase 0-F1.
- اختيار ملف PDF من لوحة إدارة المصادر.
- التحقق من نوع الملف وحجمه حتى 500 ميجابايت.
- حساب بصمة محتوى قبل الرفع لمنع التكرار.
- إنشاء مجلدات الصف والمادة ونوع المصدر عند الحاجة فقط.
- رفع الملف على أجزاء متتابعة قابلة للاستكمال.
- حفظ جلسة الرفع غير المكتملة واستكمالها بعد اختيار الملف نفسه.
- تسجيل معرف الملف ورابط عرضه وحجمه ومجلده في Supabase.
- نقل الملف إلى أرشيف واثق دون حذفه.
- استعادة الملف إلى مجلده الأصلي.
- إبقاء روابط المواقع العالمية في سجل المصادر دون رفعها كملفات.

## إعداد المرحلة

1. نفّذ SQL الموجود في:
   - `supabase/phase_0_f2_source_uploads.sql`
2. استبدل كود Edge Function الحالية بالكود الموجود في:
   - `supabase/functions/google-drive-oauth/index.ts`
3. أبقِ خيار `Verify JWT with legacy secret` مغلقًا.
4. ارفع ملفات التطبيق إلى GitHub وانتظر نجاح الفحوص والنشر.
5. اختبر رفع PDF تجريبيًا ثم تحديث الصفحة وفتح الملف من Drive.

## ما لم يتغير

- `.github/workflows/pages.yml` لم يتغير في Phase 0-F2.
- لا توجد متغيرات GitHub جديدة.
- لا توجد أسرار Supabase جديدة.

## خارج نطاق Phase 0-F2

- استخراج النصوص أو الصور من PDF.
- OCR.
- تقسيم الكتب إلى وحدات ودروس.
- تصنيف المحتوى التعليمي.
- توليد الأسئلة بالذكاء الاصطناعي.
- حفظ الاختبارات المنتجة في Drive.

## العمل عبر GitHub

- كل مرحلة في فرع مستقل.
- يفتح Pull Request إلى `main`.
- لا دمج قبل نجاح GitHub Actions والمراجعة العملية.
- تُسلَّم حزمة ملفات معدلة فقط وحزمة كاملة احتياطية.
